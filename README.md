# TS6 Droid 简中版

基于原作者 [flamme-demon/TS6_Droid](https://github.com/flamme-demon/TS6_Droid) 的开源项目进行汉化与功能增强的 Android 客户端。

这是一个自由、轻量级的 TeamSpeak 3/6 安卓客户端，使用 Jetpack Compose 构建，底层由 Rust 编写的 `tslib` 驱动。

## 更新日志

### v2.1.8-Han（2026-10-20）

**新增：在线 / 离开 / 勿扰 —— 桌面端的状态菜单**

底栏最左侧多了一个**状态圆点**（绿 = 在线、琥珀 = 离开、红 = 勿扰），点开就是桌面端那套状态菜单。
TeamSpeak 协议里只有一个 `client_away` 标记加一条离开消息，没有「勿扰」字段，所以：

- **在线**：`clientupdate client_away=0`，同时清掉离开消息
- **离开**：`client_away=1` + 离开消息，**麦克风照常可用**——这正是桌面端的语义：离开只是标记，
  不改变能不能说话
- **勿扰**：同样是 `client_away=1`，但**麦克风被真正关掉**，而且按住说话、按住密聊、开放麦
  都开不了：采集链路上加了一道独立的闸门。切回在线（或切到离开）时恢复到当前模式应有的状态——
  按住说话保持静音，语音激活 / 开放麦重新开麦
- **自定义离开消息**：菜单里直接填（最多 100 字符），留空就用默认文案（离开 / 请勿打扰）；
  消息随 `client_away_message` 发给服务器，别人长按你就能看到
- **长按自己那一行**的面板也新增「状态」一行和「修改状态」按钮，作为第二个入口
- **成员列表**：离开的成员名字本来就会变暗并带月亮角标；长按面板现在还会显示「状态」与
  「离开消息」，一眼看出对方为什么不在
- **断线重连后自动恢复**：掉线重连会建一条新连接（服务器那边回到在线），客户端记住你选的状态并在重连成功后**自动重新下发**；只有主动断开连接才复位为在线
- **不会被服务器当成刷屏**：状态切换只发**一条**命令，连点会被 600 ms 防抖合并成最后那一次、
  两条状态命令之间至少间隔 1.2 s；点已选中的状态不发命令，麦克风静音命令也只在真正变化时发。
  服务器给每个客户端的命令配额很小，超了会回 `client is flooding` 并把之后**所有**命令丢弃几十秒
  ——这正是「手机上切换了、别人却一直看到在线」的真正原因（抓包见 `CommandError: id=ClientIsFlooding`）
- 万一还是被限流：收到 `client is flooding` 后等 10 秒自动补发一次状态（只一次，不循环重试）

**修复：悬浮窗里带密码的频道无法输入密码**

悬浮窗是 `TYPE_APPLICATION_OVERLAY` 且带 `FLAG_NOT_FOCUSABLE`（不抢前台 App 的焦点），
**这种窗口收不到输入法**：密码框能看到、点它却没反应、键盘也不弹。现在打开密码框时临时让窗口
可聚焦（清掉 `FLAG_NOT_FOCUSABLE` / `FLAG_ALT_FOCUSABLE_IM`，设置
`SOFT_INPUT_STATE_VISIBLE`）并主动聚焦输入框、召唤键盘；关闭或切走时立刻恢复原状并收起键盘。

**底层**

- 原生库仍是 `tslib_multi` 8e0bc11，新增补丁
  [`patches/tslib_multi-8e0bc11-away-status.patch`](patches/tslib_multi-8e0bc11-away-status.patch)
  （叠在 v2.1.7 那份密聊补丁之上，`patch -p1` 可干净应用）：`tslib-core` 增加
  `set_away`（`clientupdate client_away` + `client_away_message` + 本地覆盖，与昵称同一套处理——
  服务端不会把 `clientupdate` 回显给发送者），`tslib-jni` 增加 `nativeSetAway`；
  状态相关的原生日志改用 `log::`（release 构建会把 `tracing` 宏编译掉，之前诊断日志里看不到）
  - 实测服务器**不会**把自己发起的状态变更回显回来（日志里没有 `reports own away`），
    所以客户端不做「按回显纠正」，只在收到时记一行日志
  - 补丁在仓库里是 LF 行尾；若在 Windows 上 `core.autocrlf=true` 的工作区里应用时报
    `different line endings`，先 `dos2unix` 该补丁文件（或 `patch --binary`）再应用即可
- 原生库按上一条相同命令重新交叉编译（arm64-v8a，`--features vendored-openssl`）
- 单元测试 75 → 79 项（状态与离开消息的映射规则，以及 Rust 侧「在线必清消息 / 空白等于没填」的归一化）

### v2.1.7-Han（2026-10-19）

**密聊（Whisper）——桌面端语义的语音密语回来了**

v2.1.5 移除密聊，是因为当时那条实现只能发文字私信：语音密语要由底层 `tslib` 把采集到的
包封装成 `C2SWhisper`，而随包的原生库没有这个接口。本次换上带密语接口的原生库
（`tslib_multi` 8e0bc11 构建）并补齐 UI 与状态机：

- **语音只发给目标（按住才路由）**：密语列表本身**不会**让麦克风常驻密聊——语音默认照常发到当前
  频道，只有**按住密聊键**时采到的包才由原生层封装为密语包发给目标（客户端 / 整个频道 /
  整个服务器组），松手立刻恢复。这样底栏两个麦克风语义不冲突：普通麦克风对频道，密聊麦克风对列表
- **两个「按住密聊」麦克风**：底栏主麦克风左侧新增琥珀色麦克风（带密语角标），悬浮窗面板内也新增
  同款按键，**长按说话即密聊**，不需要先切换任何模式；列表为空时提示先添加目标，不会静默无效。
  按住时**先切路由、再开麦**（原生集合就位后才打开麦克风），因此句子开头不会漏进频道；
  松开时**先关麦、再清路由**。按住前的麦克风状态（语音激活 / 开放麦 / 按住说话）原样恢复
- **服务器组密语（协议原生路由）**：`tslib` 新增组目标通道——`set_whisper_targets` 接收
  `groups: Vec<u64>`，按协议 1.8.2.1 的**组密语包**发送（`VoiceWhisper` + `Newprotocol` 标志 +
  `GroupWhisperType::ServerGroup` + `GroupWhisperTarget::AllChannels`），**由服务器解析组成员**。
  因此一个组只算一个目标，组内成员**后加入也立刻能听到**，成员进出、组变更、断线重连
  都不需要 App 重新下发；也不需要把组展开成客户端列表（那会受客户端目标上限限制）
- **用户组名称**：连接建立后原生层向服务器发 `servergrouplist`，组名列表随
  `nativeGetServerGroups()` 返回，密语列表里显示真实组名（未取到时回退「用户组 #id」）
- **成员用户组可见**：长按任意成员（**包括自己那一行**）打开的面板新增「服务器组」一栏，
  按服务器返回的组名列出该成员所属的组（组名未取到时显示 `用户组 #id`，组多时该栏独立滚动）；
  自己的那一行只显示身份与组信息，音量/静音/私信/密聊这些对自己无意义的操作会隐藏
- **成员频道组可见**：同一面板还会有「频道组」一行（成员在当前频道所持的频道组），
  组名来自服务器的 `channelgrouplist`（原生层连接时请求、面板打开时刷新）；
  未取到名字时显示 `频道组 #id`，拿不到组号（0）时整行隐藏而不是显示 0
- **密语列表面板**：顶栏密聊图标打开列表编辑器，分「服务器组 / 频道 / 成员」三段勾选，
  组行显示在线人数（仅供参照，组目标不占客户端名额）
- **密语列表**：成员行右侧新增密聊按钮（绿色 = 已在列表中），长按成员面板里也有开关；
  长按频道行把**整个频道**加入 / 移出列表，列表中的频道行显示绿色密聊角标
- **目标条目上限 10**：按密语条目计（服务器 `virtualserver_maxwhisperclients` 默认值），
  客户端 / 频道 / 用户组各算一个条目；超出时面板提示而不是静默失败
- **按 UID 归档**：密聊目标与私聊会话共用同一套会话键（`PrivateConversations.keyFor`），
  对方重连后目标仍然有效；**断线自动重连后列表会自动重新下发**，不用重新点一遍
- **目标离线不泄露**：目标全部离线时下发「丢弃哨兵」（客户端 0），密语包被服务器直接丢弃；
  绝不回退成频道广播，否则界面写着密聊、全频道却都听得到
- **密语指示**：顶栏绿色密聊图标（列表已配置）、聊天输入框上方「密语列表：…」横幅与占位文案、
  按住密聊时自己的头像转**琥珀色**光环（悬浮窗气泡边框同样变琥珀色），有人密语你时弹一次提示（15 秒去抖）
- **文字发给列表**：密语列表非空时输入的文字以私信发给每个在线目标（组目标发给当前在线的组成员），
  并照常归档到私信会话；频道目标只收语音（TS3 没有面向任意频道的文字命令）

**新增：频道内改临时昵称**

长按自己那一行 → 面板底部「修改临时昵称」→ 输入新昵称（3–30 字符校验，与连接页同一套规则）→
通过 `clientupdate client_nickname` 立即生效，成员列表随即显示新昵称。

- **只对当前连接有效**：不改身份文件，重连后回到连接时使用的昵称（原生层把更新后的昵称
  记在内存里做本地覆盖——服务端不会把 `clientupdate` 回显给发送者，否则成员列表会显示旧名）
- 昵称被服务器拒绝（重名/违规字符）时，仍由服务端错误提示反馈

**顺带修复：带密码的频道进不去**

此前点击一个需要密码的频道，只会在服务端被拒绝：界面不提示、也不切换，看起来就是「点了没反应」
（原生 `moveToChannel(channelId, password)` 其实早就在，缺的只是客户端入口）。

- 频道行显示**锁图标**，点之前就知道它需要密码
- 点击后弹出**密码输入框**（玻璃对话框 + 密码掩码），确认即带密码进入频道
- 密码**不保存**，只用于这一次进入；密码错误仍由服务端错误提示反馈
- **悬浮窗的频道列表同样处理**：列表内联密码输入 + 锁图标（悬浮窗是 `WRAP_CONTENT` 窗口，
  全屏对话框会被裁切，所以这里用内联输入而不是对话框）

**底层**

- 原生库基于 `tslib_multi` 8e0bc11（该提交不在上游 main 上，是 CI 构建用的个人提交）**加补丁后自行交叉编译**，
  补丁见 [`patches/tslib_multi-8e0bc11-whisper-groups.patch`](patches/tslib_multi-8e0bc11-whisper-groups.patch)
  （`git apply` 到 8e0bc11 可干净应用）：它为 `tslib-core` 增加 `whisper_groups` 组密语包发送、
  `set_nickname`（`clientupdate client_nickname` + 本地覆盖）、`servergrouplist` / `channelgrouplist`
  请求与组名读取，并为 JNI 增加 `nativeGetServerGroups`、`nativeGetChannelGroups`、
  `nativeSetNickname` 与三参数 `nativeSetWhisperTargets`；
  附带的 6 项单元测试按协议文档钉住组密语包的字节布局与「全离线不回落频道」的路由规则
- 重新构建（WSL + Linux NDK r27c + cargo-ndk，`ANDROID_NDK_HOME` 指向 NDK）：
  `cargo ndk -t arm64-v8a --platform 29 -o <out> build --release -p tslib-jni --features vendored-openssl`
  （`vendored-openssl` 不能省：`reqwest`/`native-tls` 会拉 `openssl-sys`）
- 顺带带来 `nativeSetWhisperTargets` / `nativeSetAudioSink` / `nativeWaitEvents` /
  `nativeSendPoke` / `nativeGetNetworkStats` 等接口（本次只接入密语所需的部分）
- **修掉两处 JNI 签名漂移**：`nativeMoveToChannel` 增加频道密码参数、`OpusCodec.nativeDecode`
  增加 FEC 参数。前者不改会读到不存在的参数，后者不改会把垃圾值当成标志位传进原生层
- 接收语音改为**推送式**：原生层把每包直接回调给 `AudioBridge`（这也是唯一能区分
  「密语包」与「频道包」的地方），事件式 `audio_received` 播放路径随之移除，避免双播
- 单元测试 46 → 75 项（密语目标列表与路由、组目标透传、会话键、用户组/频道组命名、昵称规则）

### v2.1.6-Han（2026-10-17）

> 本次更新参考了 [wslinnn/TS6_Droid_CN](https://github.com/wslinnn/TS6_Droid_CN) 的项目。

**安装包体积：71.7 MB → 14.9 MB**
- 开启 R8 代码压缩与资源收缩，并归档 `mapping.txt` 以便还原混淆后的崩溃栈。此前 release 包从未跑过 R8，约 11 400 个用不到的 Material 图标类被一并打进包里（dex 58.3 MB → 3.2 MB）。

**安全与隐私**
- **附件频道校验**：`ts3file://` 链接里的 `channel` 参数直接取自消息文本。此前他人只要发一条构造过的消息，就能让客户端去拉取**任意频道**的文件；现在会先校验该频道是否存在。
- **内联图片受开关约束**：聊天里的 `[img]`/图片链接此前**绕过**「自动加载图片」设置无条件加载，会把本机 IP 暴露给发送者指定的服务器；现在遵守该开关（默认关闭），改为点击加载。
- 分享链接参数改为 URL 编码（文件名含中文、空格、`&` 等不再失效）
- 同名文件在不同频道间不再串用缓存
- 过滤系统提示时不再误吞包含相同字样的用户消息
- **云备份 / 换机迁移**排除书签（含明文服务器密码）与聊天记录；此前只排除了身份私钥
- **签名口令不再写进构建脚本**：改从环境变量或本地 `keystore.properties` 读取（见[编译签名说明](#多电脑编译签名说明)）

**稳定性**
- 聊天列表同毫秒消息不再因 LazyColumn key 重复而崩溃
- 文件上传改为**先判大小再读取**，超过 10 MB 直接提示，不再把大文件整个读进内存导致 OOM
- 聊天记录改用 `org.json` 解析：此前手写扫描器遇到含 `\"` 的文本会**静默丢弃该条及其后全部历史**
- 消息被服务器拒绝时才从本地撤回（此前任意命令失败都可能误删已发送成功的消息）
- 说话状态不再永久卡死；连接瞬间到达的消息不再丢失
- 头像下载、图片预览解码、文件上传读取移出主线程；删除 PermCheck 调试日志刷屏
- 服务器以分块方式传输安装包时（无法获知总大小），更新进度不再错误地停在 100%

**语音**
- **语音激活麦克风**：麦克风模式升级为「按住说话 / 语音激活 / 开放麦克风」三选一，语音激活支持 −70 ~ −15 dB 阈值，内置迟滞、松手延迟与预发送缓冲（不吞词头词尾）
- **麦克风增益 0 ~ 400%**（0% 即关麦），解决「对方听我声音小」
- **每用户音量**：长按成员打开面板，可单独调整音量、静音、发私信，按 UID 持久化跨会话生效
- **音频焦点与回声消除**：来电、导航播报等独占音频时自动让位（可 duck 时降到 30%），结束后自动恢复，无需重连；设备支持时自动挂载 AEC，外放不再让对方听到回声
- 输出增益加软限幅，开增益不再硬削波
- 播放静默期唤醒 50 次/秒 → 4 次/秒，降低空转耗电，且不影响起播延迟
- 低延迟语音轨在部分设备初始化失败时自动去掉 `PERFORMANCE_MODE` 重建，不再无声

**网络**
- **WiFi / 蜂窝切换立即重连**：此前要等心跳超时（数秒静默）；现在平台一报告新网络就立刻重连，首次尝试不等待退避。补齐了 `ACCESS_NETWORK_STATE` 权限（缺它回调根本不会送达）

**功能**

## 多电脑编译签名说明

本项目使用 `release.keystore` 签名文件，确保各机器编译的 APK 签名一致，覆盖安装时不报签名冲突。

**仓库中不保存任何签名口令。** 构建脚本按以下顺序读取签名参数，两者都没有时回退为 debug 签名（本地开发不受影响）：

1. 环境变量 `SIGNING_KEYSTORE_FILE`、`SIGNING_STORE_PASSWORD`、`SIGNING_KEY_ALIAS`、`SIGNING_KEY_PASSWORD`（CI 使用，见下）
2. 项目根目录的 `keystore.properties`（本地使用，已被 `.gitignore` 排除）：

```properties
storePassword=你的密钥库口令
keyAlias=ts6droid
keyPassword=你的密钥口令
```

签名文件本身也已被 `.gitignore` 排除，不会提交到 GitHub；多电脑协作时，把 `release.keystore` 与 `keystore.properties` 复制到对应位置即可。

### 生成新的签名文件

如需替换签名（例如用于正式发布），在项目根目录执行：

```bash
keytool -genkey -v -keystore release.keystore -alias ts6droid -keyalg RSA -keysize 2048 -validity 10000
```

> ⚠️ 签名密钥等同应用身份：**请勿把 `release.keystore` 或口令提交到仓库或公开渠道**。一旦泄露，他人可以签出与你的应用同签名的安装包。

## 如何进行云编译 (GitHub Actions)

**默认分支推送 / 手动触发**：自动编译并运行单元测试，产出 `app-debug.apk`（未混淆，体积较大）供调试，可在 Actions 页面的 **Artifacts** 下载。

**正式发布**：推送形如 `v2.1.6-Han` 的标签后，[android-release.yml](.github/workflows/android-release.yml) 会自动：

1. 校验标签与应用版本号一致（防止忘记改版本号导致应用内检测更新出错）
2. 运行单元测试
3. 用仓库 Secrets 中的证书签名打包 release APK
4. 校验 APK 签名并在 Actions 日志打印证书指纹
5. 归档 `mapping.txt`（混淆后崩溃栈还原行号所需）
6. 计算 SHA-256 并创建 GitHub Release

需要在仓库 **Settings → Secrets and variables → Actions** 中配置：`SIGNING_KEYSTORE_BASE64`（密钥库的 Base64 编码）、`SIGNING_STORE_PASSWORD`、`SIGNING_KEY_ALIAS`、`SIGNING_KEY_PASSWORD`。
